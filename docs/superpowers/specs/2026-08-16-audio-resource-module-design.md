# 独立音频资源模块设计规格

**日期：** 2026-08-16  
**项目：** tiny-lang

## 1. 背景与目标

当前音频实现以 `AudioClip` 为核心，但实体、服务和管理端行为仍然围绕单词发音和例句音频设计。后续文章朗读、单词听写、文章听写等功能都需要共享音频资源，因此需要先将音频重构为独立基础模块。

本阶段目标是建立一个管理员维护的音频资源库，支持异步上传处理、全局唯一文件名、状态查询、重命名、失败重试、未引用删除和登录用户播放。文章、单词、例句和听写业务本阶段不接入新模块；单词和例句现有音频能力暂时移除，但其余单词能力必须继续可构建和运行。

## 2. 已确认约束

- 文章最多关联一个朗读音频，但本阶段不增加文章关联字段。
- 只有管理员可以上传、处理、重命名、重试和删除音频。
- 登录用户可以通过业务上下文播放音频，但不能浏览或枚举音频库。
- 音频处理成功即为可用，不设置独立的音频发布/下架状态。
- 删除仅允许作用于未被业务模块引用的音频；被引用时返回冲突错误。
- 音频名称保留完整文件名和扩展名，名称全局大小写不敏感唯一。
- 重名文件自动在扩展名前追加序号，例如 `lesson.mp3`、`lesson (2).mp3`。
- 开发数据库中的现有数据没有保留价值，允许通过新迁移重建音频相关结构。
- 上传开始时就创建音频记录，内容可以引用仍处于上传、处理或失败状态的音频。
- 内容发布不等待音频处理完成；播放时根据音频状态判断是否可用。

## 3. 领域模型

### 3.1 AudioResource 聚合

用新的 `AudioResource` 替代旧 `AudioClip`，作为独立聚合根。核心字段包括：

- `Id`、`CreatedById`、`LastEditorId`、`CreatedAt`、`UpdatedAt`、`ConcurrencyStamp`。
- `Name`：管理员可见名称，初始值来自完整本地文件名。
- `NormalizedName`：服务端生成的大小写不敏感比较值，建立唯一索引。
- `SourceMediaResourceId`：关联 `ResourceModule.Audio` 的源媒体资源。
- `Status`：`Uploading`、`Queued`、`Processing`、`Ready`、`Failed`。
- `DurationSeconds`、`SampleRate`、`Channels`、`ContainerFormat`、`SourceCodec`。
- `CurrentOutputVersion`、`OutputObjectName`、`LastFailureCode`。

删除旧的 `AudioClipKind`、`AudioPublicationStatus`、`PublishedAt` 以及单词/例句反向导航。音频资源不保存任何文章、单词或例句类型信息。

### 3.2 名称规则

服务层先按文件名提取显示名称，再生成规范化比较值。名称唯一性由服务层分配和数据库唯一索引共同保证：

1. 首选原始文件名。
2. 冲突时在扩展名前追加从 ` (2)` 开始的递增序号。
3. 并发竞争触发唯一约束时重新读取并分配下一个名称。
4. 管理员重命名沿用同一规则；名称冲突返回 `AudioNameConflict`，不静默覆盖其他资源。

### 3.3 业务引用边界

音频模块不维护消费者反向集合。未来文章、单词或听写实体只保存指向 `AudioResource` 的单向外键，并使用 `DeleteBehavior.Restrict`。音频删除由数据库引用完整性兜底，服务层将外键冲突映射为 `AudioInUse`。

本阶段删除单词和例句的音频外键、DTO、验证器、服务校验、管理端控件和播放逻辑，不增加文章朗读字段，也不实现听写业务。

## 4. 上传与处理流程

音频采用“两阶段上传 + 异步处理”：

1. 管理员提交文件名、扩展名、大小和内容类型，调用音频初始化接口。
2. 后端校验上传策略、分配唯一名称，创建 `MediaResource` 和 `AudioResource`，音频状态为 `Uploading`，返回音频 ID 和简单 PUT 或 Multipart 上传信息。
3. 管理端直接向对象存储上传文件，复用现有进度、Multipart、断点续传和取消能力。
4. 上传确认后激活源媒体，音频进入 `Queued` 并创建或投递处理任务。
5. 后台处理器完成解码、探测和 MP3 转码：成功进入 `Ready`，失败进入 `Failed` 并保存稳定失败码。
6. 内容模块可以在任意音频状态下保存音频 ID，也可以独立发布内容。
7. 播放接口只为 `Ready` 音频生成短期地址；其他状态返回明确的音频暂不可用错误。
8. 上传过期、中止或源对象不存在时保留音频记录并标记失败。管理员可以在原音频 ID 上重新发起上传，避免未来引用失效。
9. 处理失败且源文件有效时可以重新排队；源文件不可用时进入重新上传流程。

状态转换如下：

```text
Uploading -> Queued -> Processing -> Ready
Uploading -> Failed
Queued -> Failed
Processing -> Failed
Failed -> Uploading       (重新上传)
Failed -> Queued          (重新处理已有源文件)
```

处理任务必须幂等，不能让旧输出覆盖新输出；音频处理异常、对象存储异常和并发冲突必须转换为稳定业务错误或失败码。

## 5. API 与权限

管理员 API 提供以下用例：

- 初始化简单上传。
- 初始化 Multipart 上传。
- 查询和完成上传。
- 查询管理员音频列表和详情。
- 修改音频名称。
- 在原音频记录上重新上传失败/过期文件。
- 重新处理已有源文件。
- 删除未被引用的音频。

登录用户 API 只提供按音频 ID 获取播放地址的能力。所有响应只返回音频 ID、名称、状态、处理元数据、失败码和时间信息，不暴露对象存储路径或 provider upload ID。

稳定错误码至少包括：

- `AudioNameConflict`
- `AudioNotFound`
- `AudioInUse`
- `AudioUploadIncomplete`
- `AudioNotReady`
- `AudioProcessingFailed`
- `AudioStatusConflict`

## 6. 管理端范围

新增独立音频管理页面，包含：

- 音频列表、名称搜索和状态筛选。
- 文件选择、简单上传和 Multipart 上传进度。
- `Uploading / Processing / Ready / Failed` 状态展示。
- 音频重命名。
- 失败重试和失败资源重新上传。
- 未引用音频删除。
- `Ready` 音频试听。

原有单词页面中的 `WordAudioPicker`、`WordAudioUploadControl` 和单词专用音频 API 本阶段移除。未来消费者使用独立音频模块的 `AudioResourceId` 接入。

## 7. 数据库与后台处理

- 保留历史 EF Core migration 文件，新增音频模块重建 migration。
- 删除旧音频表、旧音频处理任务关联，以及单词/例句音频外键和相关索引。
- 创建 `audio_resources`、新的处理任务关系和 `NormalizedName` 唯一索引。
- `MediaResource` 的音频模块和通用上传会话继续复用。
- 更新音频处理 dispatcher、worker、转码和清理维护逻辑以使用 `AudioResource` 与新状态机。
- 不修改文章朗读、听写或单词学习的数据模型。

## 8. 验收与测试

### 后端

- 名称大小写不敏感唯一、并发重名分配和扩展名处理。
- 两阶段上传、简单 PUT、Multipart、断点续传和状态转换。
- 处理成功、失败、重试和任务幂等。
- 上传过期/中止/对象缺失转为失败状态。
- 非 `Ready` 播放返回稳定错误，`Ready` 播放返回短期地址。
- 被引用音频删除返回 `AudioInUse`。
- 管理员与普通登录用户授权边界。
- OpenAPI 不再暴露旧 `AudioClipKind`、发布/下架接口或单词专属音频契约。
- 单词模块移除音频后仍能创建、编辑、发布和学习。

### 管理端

- 音频列表、搜索、状态筛选和详情。
- 上传进度、取消、失败提示和重试。
- 重命名冲突提示。
- 未引用删除成功、已引用删除冲突。
- Ready 音频试听和非 Ready 不可播放提示。

## 9. 非本阶段范围

- 文章朗读音频字段和文章编辑器适配。
- 单词发音、例句音频和单词学习音频适配。
- 单词听写、文章听写业务。
- 数据迁移和旧开发数据兼容。
- 视频模块改造。
