# 单词批量导入与音频批量上传设计规格

**日期：** 2026-08-17
**项目：** tiny-lang

## 1. 背景与目标

当前单词模块只支持管理员逐条创建单词，音频库也只支持一次选择一个本地文件。管理员在录入大量单词、释义和例句时，需要重复执行相同操作，无法通过结构化数据高效完成初始化。

本阶段增加两项相互配合但保持独立的管理能力：

1. 音频库支持一次选择多个本地音频，并逐文件复用现有上传、确认和处理生命周期。
2. 单词模块支持上传 JSON，按音频库中的最终完整文件名关联单词音频和例句音频，经预览校验后原子创建整批单词。

批量创建必须与当前单条创建能力一致，覆盖单词、词性、释义、用法说明、单词音频、例句、例句译文和例句音频。本阶段不修改 `/app` 用户端，不改变数据库结构，也不恢复已经删除的旧批量导入契约。

## 2. 已确认约束

- 单次最多导入 1000 个单词。
- JSON 文件及后端请求体最大为 20 MB。
- 任意一行失败都会使整批失败，不允许部分写入。
- JSON 内同名单词或与数据库已有单词冲突时，整批失败。
- 批量导入只创建新单词，不跳过、不覆盖或更新已有单词。
- 单词音频和例句音频均可省略，不要求每项都有音频。
- 引用音频时，资源必须存在。
- 允许关联 `Uploading`、`Queued`、`Processing` 和 `Ready` 状态的音频资源。
- 不允许关联 `Failed` 状态的音频资源。
- 词性使用英文枚举名称字符串，不接受枚举数字。
- 管理端采用“校验预览 -> 管理员确认 -> 原子导入”的两阶段流程。
- 音频批量上传逐文件独立处理；成功文件保留，失败文件可单独重试。
- 同名音频继续使用现有自动添加序号后缀的规则，例如 `hello (2).mp3`。
- JSON 必须使用音频库中的最终完整文件名，包括扩展名。
- 音频文件名匹配忽略大小写和首尾空格，与 `AudioResource.NormalizeName` 保持一致。

## 3. 方案选择

采用无状态两阶段导入：

```text
POST /api/admin/words/batch/validate
POST /api/admin/words/batch
```

校验接口解析完整请求、批量查询数据库、解析音频名称并返回规范化预览和全部可识别错误，不写入数据库。导入接口接收相同业务数据，不信任先前结果，重新执行完整校验，再在单个数据库事务中写入全部单词聚合。

不采用仅由前端执行预览校验的方案，因为前端无法可靠判断数据库已有单词、音频最终名称和资源状态。不采用异步导入任务，因为 1000 条上限下同步校验和事务写入足够，任务表、状态机和结果留存没有必要。

音频批量上传不增加后端批量协议。管理端通过有界并发逐文件调用现有单文件上传接口，保持单个文件的简单上传、分片上传、确认、处理、失败清理和重试语义不变。

## 4. JSON 契约

### 4.1 文件结构

JSON 使用带根对象的结构，为后续增加契约版本或导入选项保留扩展空间：

```json
{
  "words": [
    {
      "headword": "hello",
      "audioFileName": "hello.mp3",
      "senses": [
        {
          "partOfSpeech": "Interjection",
          "definition": "你好；喂",
          "usageNote": null,
          "sortOrder": 0,
          "examples": [
            {
              "sentence": "Hello, how are you?",
              "translation": "你好，你怎么样？",
              "audioFileName": "hello-example-1.mp3",
              "sortOrder": 0
            }
          ]
        }
      ]
    }
  ]
}
```

根节点必须是对象，`words` 必须是非空数组且最多包含 1000 项。批量输入不接受单词、释义、例句的数据库 ID，不接受并发标识、状态或音频资源 ID。

### 4.2 字段规则

- `headword`、`senses`、释义和例句字段继续使用当前单条创建的长度、数量、排序和必填规则。
- `partOfSpeech` 只接受 `Noun`、`Verb`、`Adjective`、`Adverb`、`Pronoun`、`Determiner`、`Preposition`、`Conjunction`、`Interjection`、`Numeral`、`Particle` 和 `Other`。
- `audioFileName` 省略、为 `null` 或为空字符串时均表示不关联音频。
- 非空 `audioFileName` 必须在音频库中唯一匹配一个资源，并且该资源不能处于 `Failed` 状态。
- 同一个音频资源可以被批内多个单词或例句复用。
- 单词重复判断继续使用单词实体的规范化规则；大小写或首尾空格不同但规范化结果相同的单词视为重复。

### 4.3 文件大小与集合限制

Endpoint 使用 20 MB 请求体限制，管理端在发起请求前执行相同限制。服务端还必须保留单个单词的现有释义和例句数量上限，并对整批嵌套集合和总文本量设置有界限制，防止用 1000 个合法根项包装异常大的对象图。

## 5. 后端契约

### 5.1 批量输入 DTO

新增批量专用 DTO，将 `audioFileName` 与单条创建使用的 `AudioResourceId` 隔离。批量 DTO 只表达外部 JSON 格式；音频解析完成后转换为现有 `CreateWordRequest` 形状，并复用单条创建的字段验证规则。

批量 DTO 的 `partOfSpeech` 使用字符串属性接收，再由批量校验器逐行解析为 `PartOfSpeech`。不能直接把该字段声明为枚举，否则未知名称会在 JSON 模型绑定阶段终止整个请求，无法返回具体行和字段错误。解析成功后生成的内部请求仍使用现有枚举类型。

批量 DTO 包括：

- 根请求和 `Words` 集合。
- 单词行及可选 `AudioFileName`。
- 释义输入。
- 例句输入及可选 `AudioFileName`。

客户端不能为任何嵌套项指定持久化 ID。

### 5.2 校验响应

`POST /api/admin/words/batch/validate` 对能够反序列化的请求返回 `200 OK`。响应至少包含：

- `isValid`：整批是否可以提交。
- 单词、释义、例句、单词音频引用和例句音频引用统计。
- 每一行的 `rowNumber`，从 1 开始。
- 规范化后的单词预览和音频匹配摘要。
- 完整错误列表，每项包含 `rowNumber`、稳定错误码、字段路径和管理员可读消息。

字段路径使用完整 JSON 路径，例如：

```text
words[2].senses[0].examples[1].audioFileName
```

校验应尽可能收集整批所有可识别错误，而不是遇到第一项错误就停止。非法 JSON 由模型绑定返回 `400 Bad Request`，超出请求体限制返回相应请求过大响应。

### 5.3 导入响应

`POST /api/admin/words/batch` 接收与校验接口相同的请求：

- 重新校验失败时返回 `422 Unprocessable Entity`，正文使用与校验接口一致的错误结构。
- 成功时返回 `200 OK`，包含 `createdCount` 和每个 `rowNumber` 对应的新 `wordId`。
- 不创建导入任务记录或导入批次表。

### 5.4 OpenAPI

OpenAPI 契约需要覆盖：

- 两个管理员批量接口及管理员授权要求。
- 20 MB 请求体限制对应的接口元数据。
- 批量请求、统计、预览、逐行错误和成功响应 schema。
- `partOfSpeech` 在批量输入 schema 中为受支持名称组成的字符串集合，不接受数字。
- 批量输入中不存在 `AudioResourceId`、持久化 ID、并发和状态字段。

## 6. 批量校验与音频解析

### 6.1 校验顺序

服务端按以下顺序处理请求：

1. 验证根结构、单词数量、嵌套集合总量和文本总量。
2. 对每一行执行当前单条创建的字段和局部集合规则。
3. 规范化全部 `headword`，检查批内重复。
4. 一次查询数据库中可能冲突的已有单词。
5. 收集并规范化全部非空音频文件名。
6. 一次查询匹配的音频资源，检查不存在和 `Failed` 状态。
7. 将成功解析的文件名转换为 `AudioResourceId`，形成规范化预览或待创建模型。

数据库查询必须以集合方式执行，不能针对每个单词或每个音频名称逐项查询。

### 6.2 共享逻辑边界

单条创建和批量创建共享以下能力：

- 单词、释义和例句字段验证。
- 音频资源存在性规则。
- 从已验证请求构建 `Word`、`WordSense` 和 `ExampleSentence` 聚合。
- 数据库唯一约束和外键异常分类。

批量服务不能循环调用当前 `CreateAsync`，因为该方法会逐项保存，无法保证整批原子性。应抽取不执行保存的聚合构建方法，由单条创建和批量创建在各自事务边界内使用。

## 7. 原子导入与并发

导入接口不使用校验阶段生成的服务器临时状态，而是重新读取当前数据库并执行完整校验。这样可以处理预览后发生的以下变化：

- 另一个管理员创建了同名单词。
- 音频被重命名或删除。
- 音频从可关联状态转为 `Failed`。

全部校验通过后，在单个数据库事务中构建所有单词聚合并统一保存。任意实体保存失败都回滚整个事务，不留下单词、释义或例句的部分数据。

数据库中的单词规范化唯一索引和音频外键继续作为并发场景的最终保护：

- 并发同名单词唯一约束冲突转换为明确的批量冲突错误，不泄漏 `DbUpdateException`。
- 校验后音频被删除导致的外键异常转换为对应音频字段错误。
- 与批量导入无关的数据库异常继续向全局异常处理器传播，不能被误分类。

## 8. 音频库批量上传

### 8.1 范围与复用

只在 `admin` 音频库页面增加批量上传入口。单词编辑器、例句编辑器和其他资源选择器中的本地上传继续使用单文件交互。

批量控件复用当前 `AudioUploadControl` 已实现的能力，或将其中单文件上传流程抽取为可复用的无界面执行单元。不能复制一套简单上传、分片上传和处理轮询协议。

### 8.2 并发与状态

- 文件选择器支持 `multiple`。
- 同时最多处理 2 个文件。
- 单个大文件内部继续使用现有最多 3 个分片并发。
- 每个文件独立显示等待、初始化、上传进度、完成上传、确认、后台处理、成功或失败状态。
- 取消或失败只影响对应文件，不中断其他文件。
- 成功文件保留；失败文件可以单独重试。

### 8.3 最终文件名

服务端继续使用当前自动重命名逻辑。同名文件上传后可能得到 `name (2).mp3`、`name (3).mp3` 等最终名称。

批量结果必须明确展示：

```text
本地文件名 -> 音频库最终文件名
```

管理员编写 JSON 时必须使用最终文件名。批量上传完成后刷新音频列表，但不能因列表刷新清除当前批次的逐文件结果。

## 9. 管理端单词导入

### 9.1 入口与页面

单词列表页增加“批量导入”按钮，进入独立 `/words/batch` 页面。页面提供一份符合正式契约的示例 JSON 下载，并列出可使用的英文词性名称。

### 9.2 文件选择和预检

管理端在请求后端前执行轻量预检：

- 文件扩展名必须为 `.json`。
- 文件不能超过 20 MB。
- 文件内容必须能被 `JSON.parse` 解析。

前端不复制后端完整业务验证规则。数据库冲突、音频匹配、嵌套字段规则和最终可导入性以服务端结果为准。

### 9.3 校验预览

上传 JSON 后自动调用校验接口。页面展示：

- 单词、释义和例句数量。
- 单词音频和例句音频的引用与匹配数量。
- 每行规范化后的单词摘要。
- 行号、单词、字段路径和错误信息。

管理端不提供 JSON 内联编辑器。管理员修改源文件后重新选择，避免在浏览器中维护另一份容易与源文件分叉的数据。

只有 `isValid` 为 `true` 时才启用“确认导入”。选择新文件或重新校验后，先前校验结果失效。

### 9.4 提交和结果

确认提交期间禁用文件替换、再次校验和重复提交。成功后返回单词列表并显示实际创建数量。

如果正式导入因数据变化返回 `422`，页面保留当前文件和输入数据，使用最新错误结果替换预览，并要求管理员修正或重新校验后再提交。网络错误允许使用相同数据重试；若第一次请求实际成功，重复请求会因现有同名单词而整批失败，不会重复创建。

## 10. 错误处理

批量功能需要增加稳定错误语义，覆盖：

- 批量根结构无效。
- 单词数量、嵌套集合总量、文本总量或请求体超限。
- 批内规范化单词重复。
- 数据库已有同名单词。
- 音频文件名不存在。
- 音频资源状态为 `Failed`。
- 正式导入期间发生并发单词冲突或音频外键失效。

逐行错误应尽量绑定到具体字段路径；无法绑定到单行的根级限制使用批量级错误。所有数据库异常只在命中明确约束时转换，其他异常保留现有全局处理行为。

音频批量上传继续使用现有音频上传错误码。批量控件负责把错误绑定到具体文件，并确保一个文件失败不会覆盖其他文件的成功信息。

## 11. 测试策略

### 11.1 后端

- 批量 DTO 接受合法根结构并拒绝空集合、超过 1000 项和超限嵌套集合。
- 字符串词性合法，枚举数字和未知名称被拒绝。
- 音频名称省略、`null` 和空字符串均转换为无关联。
- 音频名称匹配忽略大小写和首尾空格。
- `Uploading`、`Queued`、`Processing` 和 `Ready` 音频可以关联，`Failed` 音频被拒绝。
- 同一音频可被多个单词和例句复用。
- 批内规范化单词重复和数据库已有单词均返回精确行错误。
- 多种错误可以在一次校验响应中完整返回。
- 音频和已有单词解析使用有界集合查询，不产生逐行查询。
- 校验接口不写入任何实体。
- 导入任意一行无效时数据库零写入。
- 成功导入完整创建单词、释义、例句及音频外键。
- 保存异常时整个事务回滚。
- 预览后单词或音频状态变化时重新校验失败。
- 唯一约束和音频外键竞态映射为稳定错误，其他数据库异常不被误映射。
- Endpoint 权限、20 MB 限制、`200`、`400`、`422` 和 OpenAPI schema 正确。

### 11.2 管理端音频库

- 文件选择器允许多选并显示全部待上传项。
- 同时活跃的文件上传不超过 2 个。
- 每个文件独立更新进度和终态。
- 一个文件失败不阻止其余文件完成。
- 失败文件可以单独重试。
- 自动重命名后展示本地名称和最终名称。
- 列表刷新不清除当前批次结果。

### 11.3 管理端单词导入

- 列表入口和 `/words/batch` 路由仅对管理员开放。
- 拒绝非 JSON、空文件、非法 JSON 和超过 20 MB 的文件。
- 合法文件会调用校验接口并展示统计和规范化预览。
- 错误列表正确显示行号、字段路径和消息。
- 校验未通过时不能确认导入。
- 提交期间不能替换文件或重复提交。
- 正式导入重新校验失败时保留页面并更新错误。
- 成功后返回单词列表并展示创建数量。
- 示例 JSON 与正式契约保持一致。

## 12. 非目标

- 不修改 `/app` 用户端单词展示或学习流程。
- 不增加数据库表、字段或 migration。
- 不支持 CSV、Excel、ZIP 或在 JSON 中嵌入音频数据。
- 不支持批量更新、覆盖、跳过已有单词或部分成功。
- 不增加异步导入任务、任务历史或导入撤销。
- 不在管理端提供 JSON 在线编辑器。
- 不改变单词和例句编辑器现有的单文件音频上传交互。

## 13. 验收标准

1. 管理员可以在音频库一次选择多个文件，各文件独立完成上传并看到最终资源名称。
2. 管理员可以上传符合契约的 JSON，预览全部统计、音频匹配和错误信息。
3. 任意错误都会阻止确认导入，并且数据库中不产生任何批内单词。
4. 全部校验通过后，管理员可以一次原子创建最多 1000 个完整单词聚合。
5. 正式导入前发生的单词或音频变化会被重新校验捕获，不产生部分数据。
6. 单条创建、编辑和现有音频上传功能保持原有行为。
7. 后端测试、管理端测试、Lint 和生产构建全部通过。
