# 单词模块重构与共享音频适配设计规格

**日期：** 2026-08-17  
**项目：** tiny-lang

## 1. 背景与目标

独立 `AudioResource` 模块和文章朗读音频支持已经完成，但单词模块仍使用发布状态、多发音文本元数据和创建者/编辑者审计关系，且尚未接入共享音频资源。现有用户端单词学习页面也保留了旧的多发音和例句音频前端类型，与当前后端契约不一致。

本阶段通过原地简化现有单词聚合完成重构：单词保存后立即有效，每个单词最多关联一个可空的共享音频资源；保留释义、可空例句、词头规范化、乐观并发和现有单词学习流程。管理端复用文章朗读音频的交互模式，允许从音频库选择或直接上传并关联。

## 2. 已确认约束

- 删除单词发布状态；单词创建成功后立即有效。
- 删除发布、下架和归档生命周期及其时间字段和管理操作。
- 删除 `CreatedById`、`LastEditorId`、`CreatedBy`、`LastEditor`，但保留 `CreatedAt`、`UpdatedAt`。
- 保留 `ConcurrencyStamp` 乐观并发控制，更新和删除仍要求客户端提供并发标识。
- 每个单词必须至少有一个释义。
- 每个释义可以没有例句；已有例句仍必须同时包含正文和译文。
- 每个单词最多关联一个可空的共享音频资源。
- 删除 IPA、口音标签、默认发音和多发音排序能力。
- 管理员可以关联任意处理状态的音频；只有 `Ready` 音频可以通过共享播放接口播放。
- 本阶段不恢复例句音频，不实现派生词、自引用、单词听写或文章听写。
- 开发数据库中的单词及单词学习数据没有保留价值，使用破坏式迁移，不编写历史数据转换逻辑。
- 单词删除采用数据库级联约束删除直接关联的单词学习记录，不增加历史数据修复流程。

## 3. 领域模型

### 3.1 Word 聚合根

`Word` 保留以下核心内容：

- `Id`、`Headword`、`NormalizedHeadword`。
- `CreatedAt`、`UpdatedAt`、`ConcurrencyStamp`。
- 有序 `Senses` 集合及每个释义下的有序 `Examples` 集合。
- `Guid? AudioResourceId` 和 `AudioResource? AudioResource`。
- 用户单词进度和单词学习会话项目导航。

从 `Word` 删除：

- `Status`、`PublishedAt`、`ArchivedAt`。
- `CreatedById`、`LastEditorId`、`CreatedBy`、`LastEditor`。
- `Pronunciations` 集合。

`Word` 继续继承包含创建和更新时间的基础实体。`ConcurrencyStamp` 继续作为 EF Core 并发令牌，防止多个管理员的编辑互相静默覆盖。

### 3.2 单音频关联

删除 `WordPronunciation` 实体、EF Core 配置、DbSet、DTO 和 `word_pronunciations` 表。单词直接保存一个可空的 `AudioResourceId`：

- 外键使用 `DeleteBehavior.Restrict`。
- 音频模块不增加单词反向导航，保持消费者单向引用边界。
- 删除单词只解除引用，不删除共享音频资源。
- 删除被单词引用的音频时，由现有音频服务将外键冲突映射为 `AudioInUse`。
- 单词保存只验证音频 ID 合法且资源存在，不要求状态为 `Ready`。

### 3.3 释义与例句

释义仍是单词聚合内必须存在的有序子项。创建和更新请求至少包含一个释义，每个释义继续要求合法词性和非空释义文本。

例句集合可以为空。存在例句时，例句正文、翻译、子项 ID 所属关系和排序规则保持不变。本阶段不给 `ExampleSentence` 增加 `AudioResourceId`。

### 3.4 删除关系

`UserWordProgress.WordId` 和 `WordStudySessionItem.WordId` 改为级联删除。服务层不再因为存在学习历史而拒绝删除单词。由于迁移会破坏性重建单词学习相关结构，本阶段不设计旧会话迁移、重排或统计修复逻辑。

## 4. 服务与 API

### 4.1 管理用例

`IWordService` 保留创建、更新、删除、管理详情和管理列表用例。`CreateDraftAsync` 重命名为 `CreateAsync`，删除 `PublishAsync`、`UnpublishAsync` 和 `ArchiveAsync`。

管理 API 只保留：

- `POST /api/admin/words`
- `GET /api/admin/words`
- `GET /api/admin/words/{id}`
- `PUT /api/admin/words/{id}`
- `DELETE /api/admin/words/{id}`

发布、下架和归档路径不再注册，也不出现在 OpenAPI 中。更新和删除继续校验 `ConcurrencyStamp`。

### 4.2 写入契约

创建和更新请求包含：

- `headword`
- `audioResourceId`
- `senses`

删除 `pronunciations`。更新仍使用完整目标集合语义：请求中不存在的已有释义或例句会被删除，保留子项通过 ID 更新，新子项不携带 ID。

音频 ID 为 `Guid.Empty` 时返回请求验证错误；音频资源不存在时返回稳定的 `WordAudioInvalid`。关联处于 `Uploading`、`Queued`、`Processing` 或 `Failed` 状态的音频合法。

### 4.3 响应契约

管理详情返回一个可空的单词音频摘要，包含：

- `id`
- `name`
- `status`
- `durationSeconds`
- `lastFailureCode`

管理列表不返回完整音频对象，使用 `bool HasAudio` 表示是否已关联音频。管理响应不再包含状态、发布/归档时间和创建者/编辑者摘要。

用户单词列表、详情和单词学习内容只返回可空的 `audioResourceId`，不返回音频名称、处理状态、对象存储信息或上传信息。

### 4.4 用户可见性与排序

`WordVisibilityPolicy` 删除发布状态、发布时间、发音集合、默认发音和例句必须存在的条件。策略只保留至少存在一个有效释义的防御性条件。

用户单词列表和顺序选词不再依赖 `PublishedAt`，改为按 `UpdatedAt` 降序、`Id` 降序形成稳定顺序。随机选词、已学习排除、每日学习设置和结果提交逻辑保持不变。

## 5. 错误处理

保留以下既有错误语义：

- 单词不存在、重复规范化词头。
- 非法词性、缺少释义、非法例句文本。
- 子项 ID 不属于当前聚合、重复排序值。
- `ConcurrencyStamp` 过期或数据库并发冲突。

新增或调整以下语义：

- `WordAudioInvalid`：音频 ID 为空 GUID 或引用的音频不存在。
- `AudioNotReady`：用户尝试播放非 `Ready` 音频，由共享音频播放接口返回。
- `AudioInUse`：管理员尝试删除被文章或单词引用的音频。

删除只服务于发布状态、多发音和学习历史删除保护的错误码。数据库唯一约束、外键约束和并发异常继续映射为稳定业务错误，不能暴露通用 500。

## 6. 管理端设计

### 6.1 单词列表

删除状态筛选、状态徽标、发布/下架/归档操作和审计用户列。列表保留：

- 词头、首要词性和首要释义。
- 释义数、例句数。
- 是否已关联音频。
- 创建时间、更新时间。
- 编辑和删除操作。

筛选保留关键词、词性、释义文本和分页大小。删除确认对话框继续携带并发标识。

### 6.2 单词编辑器

编辑器删除多发音列表、口音标签、IPA、默认发音复选框、发布按钮和状态只读限制。表单始终允许编辑，保存成功文案不再使用“草稿”。

音频交互学习文章朗读音频控件：

1. 管理员可以打开 `AudioResourcePickerDialog`，按名称和状态从音频资源库选择一个资源。
2. 管理员可以使用 `AudioUploadControl` 从本地上传新音频。
3. 上传初始化成功后立即把新的音频 ID 关联到当前单词表单，不等待后台处理完成。
4. 控件展示音频名称和处理状态，并支持解除关联。
5. 处理失败只展示状态和提示，不自动清除关联。

新增领域文案专用的 `WordAudioControl`，使用现有音频基础组件组合实现。复用现有音频选择、上传和状态契约，不增加单词专属上传 API。

## 7. 用户端设计

现有 `/words` 页面继续作为单词学习页面，本阶段不新增独立词典或单词详情页面。

- 学习内容类型由 `pronunciations[]` 改为 `audioResourceId: string | null`。
- 有音频时在词头旁展示播放按钮；没有音频时不显示占位控件。
- 复用 `requestAudioPlayback` 和共享播放器状态逻辑，不保留 `requestWordAudio` 或重复的播放请求实现。
- 为共享 `AudioPlaybackButton` 增加 `variant="icon"` 紧凑模式；文章继续使用默认完整按钮，单词学习使用图标模式。
- 例句类型删除旧的 `audioClipId`，学习卡片不再渲染例句播放按钮。
- 没有例句的释义仍正常展示词性、释义和用法说明。

## 8. 数据库迁移

保留已有历史 migration 文件，新增一个明确标注破坏性的 EF Core migration。迁移只处理单词领域及其学习关系，不删除文章、用户、音频资源、试卷或视频模块数据。

迁移目标包括：

- 删除单词状态、发布/归档时间和审计用户外键/索引。
- 删除 `word_pronunciations` 表。
- 为 `words` 增加可空 `AudioResourceId`、索引和 Restrict 外键。
- 将用户单词进度和学习会话项目到单词的外键改为级联删除。
- 清空或重建现有单词、释义、例句、用户单词进度、学习会话和会话项目数据。
- 更新 EF Core model snapshot。

## 9. 验收与测试

### 9.1 后端

- 模型不再包含状态、审计用户关系或 `WordPronunciation`。
- 单词存在一个可空的共享音频外键，删除被引用音频返回 `AudioInUse`。
- 无音频、任意音频处理状态和解除音频关联均可保存。
- 不存在的音频返回 `WordAudioInvalid`。
- 创建和更新必须至少包含一个释义，例句集合可以为空。
- 更新继续正确同步释义、例句和排序，并保护并发写入。
- 新建单词立即出现在用户查询和单词学习候选范围。
- 删除单词可以级联删除直接关联的学习记录。
- OpenAPI 不包含单词发布生命周期、多发音 DTO 或审计用户字段。

### 9.2 管理端

- 列表不再提供状态筛选和生命周期操作。
- 编辑器可以从音频库选择、从本地上传并立即关联、解除音频关联。
- 音频任意状态均能显示并保存。
- 创建、更新、并发冲突、嵌套字段验证和删除确认行为正常。
- API contract 能拒绝结构不符合新响应模型的数据。

### 9.3 用户端

- 有音频的单词可以通过共享播放接口播放。
- 无音频的单词不展示播放按钮。
- 非 `Ready` 音频显示稳定的暂不可用错误。
- 无例句释义正常渲染。
- 单词学习会话、目录、结果提交和每日设置保持可用。

### 9.4 最终验证

- 运行后端完整测试和构建。
- 运行 `admin` 完整测试、lint 和生产构建。
- 运行 `app` 完整测试、lint 和生产构建。
- 扫描生产代码，确认不存在 `WordPublicationStatus`、`WordPronunciation`、`pronunciations`、`PublishedAt` 单词依赖、单词审计用户关系及旧 `audioClipId` 运行时代码。

## 10. 非本阶段范围

- 派生词和其他单词自引用关系。
- 例句音频。
- 单词听写和文章听写。
- 独立用户词典或单词详情页面。
- 旧开发数据迁移和兼容层。
- 视频、试卷或文章模块的其他重构。
