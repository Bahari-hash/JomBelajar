# 单词背诵与个人主页内容收纳设计

## 目标

减少单词背诵阶段的直接提示，支持用户先回忆再查看释义和例句；同时降低个人主页的内容密度，将单词学习与账户安全整理为默认折叠的模块，并将收藏本、停止复习列表改为按需打开的弹窗。

## 范围

- 仅修改 `/app` 前端。
- 不修改后端接口、数据库和路由。
- 不改变拼写阶段、学习提交、收藏接口和停止复习恢复接口的业务行为。

## 交互设计

### 单词背诵卡片

`WordMemorizationCard` 保留单词标题、单词音频和收藏入口。每个词义使用默认收起的原生 `<details>`：摘要行显示词性和“释义”，展开后显示释义与用法说明。词义下的例句使用第二层默认收起的 `<details>`，摘要显示例句数量；展开后显示句子、翻译及已有例句音频按钮。没有例句时不渲染例句入口。

### 个人主页

`ProfilePage` 将内容整理为两个默认收起的原生 `<details>`：

- “单词学习”：展开后显示学习统计、学习设置，以及打开收藏本和打开停止复习的入口按钮。
- “账户安全”：展开后显示现有修改邮箱、重置密码和删除账号表单。

收藏本与停止复习列表从主页主体移除，分别在 DaisyUI modal 中按需挂载。弹窗提供标题、关闭按钮、`role="dialog"` 和 `aria-modal="true"`，在小屏幕使用接近全宽布局，在大屏幕限制最大宽度。弹窗关闭时卸载面板，避免在主页默认状态下发起列表查询。

## 组件边界

- `WordMemorizationCard` 只负责单个学习项的展示和折叠，不管理学习提交状态。
- `WordFavoritesPanel` 与 `WordReviewExclusionsPanel` 增加弹窗适配属性或包装层，保留现有查询、分页、错误处理和操作逻辑。
- `ProfilePage` 负责顶层折叠和弹窗开关，不接管列表内部业务状态。
- `AccountSecurityPanel` 保持现有表单实现，仅由主页折叠容器控制显示。

## 可访问性与错误处理

- 优先使用原生 `<details>/<summary>`，获得键盘和语义支持。
- 弹窗使用现有项目的 dialog 结构，按钮提供明确的可访问名称。
- 列表查询失败、取消收藏失败、恢复复习失败继续显示在对应面板或弹窗内，不改变现有错误文案和重试行为。
- 关闭弹窗不清除后端数据，只卸载当前视图；重新打开时重新读取最新数据。

## 验证

- 增加背诵卡片测试：释义默认不可见，展开后可见；例句入口默认不可见，展开后可见；无例句时不显示入口。
- 更新个人主页测试：两个顶层模块默认收起；点击入口打开对应 dialog；关闭后 dialog 内容卸载。
- 运行相关 Vitest 测试、前端 lint 和生产构建。
